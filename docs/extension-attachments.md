# VS Code workspace image insertion design

Milestone 2.2 defines the workflow for a later implementation. Folio's VS Code adapter currently renders supported workspace images through `extension/src/resources.ts`. Its upload operation remains disabled. Standalone image import uses the browser adapter and stores an embedded image with the document.

## Selection and destination

1. Add an **Image from file** action in the VS Code editor. Use a webview file input for the desktop user's local file, including when the workspace extension host runs on another machine. Read one file, cap it at 5 MiB before allocating or transferring it, and send bounded bytes plus the display filename through the existing connection envelope. A browser MIME type is an early filter. The host validates the byte count, extension, and raster signature using the same formats as workspace preview. Reuse the existing image dialog for alt text and insertion. Start with this picker flow before considering drag and drop or paste. [VS Code Remote webviews](https://code.visualstudio.com/api/advanced-topics/remote-extensions#using-the-webview-api)
2. The host derives the document and workspace folder from the active custom editor session. Require a saved file in a writable, supported workspace folder. A called operation is bound to that document URI, containing folder URI, and connection. Offer the document-relative `assets/` directory by default. An optional resource-scoped `folio.attachments.directory` setting can specify a path relative to the containing workspace folder. Preview the target before writing. Validate settings from the workspace using the same rules as user-supplied paths, and check provider writability again when starting a write. A provider-wide writable result can coexist with read-only directories or a read-only Markdown document. Handle per-file metadata and actual write or permission errors. [VS Code FileSystem API](https://code.visualstudio.com/api/references/vscode-api#FileSystem)
3. Sanitize the basename for portability across Windows, macOS, and Linux. Strip path components, normalize Unicode to NFC, remove controls and Windows-reserved characters, and trim trailing dots and spaces. Use `image` for an empty stem or a Windows device name. Limit the stem to 100 UTF-8 bytes on a code point boundary and derive the lowercase extension from the validated format. Keep the original display stem for alt text. On collision, try `name-2.ext` through `name-100.ext`. Use a no-overwrite filesystem operation for the final name even when a preceding stat found it free. Treat canonically equivalent or case-folded existing filenames in that directory as collisions for checkout portability.
4. Calculate the link from the document's parent URI to the finalized asset URI using POSIX URI path segments. Verify that both URIs are in the same workspace folder, scheme, and authority. Percent-encode each filename segment once, including spaces, `#`, `%`, and parentheses. Keep `/` between segments and emit `./assets/name.png` or bounded `../` steps. Test the emitted reference through the existing resolver before returning it to the webview. Save only the relative reference in Markdown.

## Filesystem boundary

Put validation and publication in a host service next to `extension/src/resources.ts`. Share the raster signature checks and lexical containment rules with resource reads where their semantics match. Use URI segments, `Uri.joinPath`, and `workspace.fs` for provider-backed resources. Disallow absolute and parent segments in the configured asset directory. Walk from the selected root and reject symlinks, non-directories, encoded separators, controls, device names, and root or authority changes. Recheck the nearest existing parent before directory creation, then verify every component. For a `file` URI available to the extension host, also check canonical containment and use an exclusive, no-follow stage creation primitive where available. Revalidate before publication and after reading the final bytes. [VS Code virtual workspace guidance](https://code.visualstudio.com/api/extension-guides/virtual-workspaces)

Before enabling a provider for insertion, establish that it reports link metadata accurately and supports an exclusive staging create plus a same-directory no-overwrite publication under concurrent writes. For a provider that cannot satisfy these requirements, surface an unsupported destination before creating files. Document the guarantee for each supported provider.

A `file` URI, a successful preview, or a writable provider are insufficient. [VS Code Remote extension guidance](https://code.visualstudio.com/api/advanced-topics/remote-extensions) |

Use a trusted, saved, writable document in the containing workspace folder. Validate the proposed directory as portable relative components before filesystem access, including sibling roots, encoded separators, parent traversal, reserved device names, and reparse points. Compare URI schemes and authorities as well as complete path segments. Recheck canonical containment, but treat checks followed by path-based operations as race-prone. Before enabling a backend, demonstrate an anchored operation or an independently enforced destination boundary under a parent-swap test. Cleanup has the same constraint. A digest and file identity aid classification, but a subsequent path-based unlink can still target a replacement. Leave ambiguous or unprotected stages for review.

The final link operation protects the filesystem's own name equivalence. Folio must also check NFC and case-folded collisions for portability and serialize candidate selection among its own concurrent requests. Where the host filesystem permits equivalent spellings, a directory listing alone cannot prevent a non-cooperating writer from racing that check. Keep the initial supported scope narrow enough to meet the chosen collision contract and record it in qualification tests.

Keep the webview picker on the client and validate the declared and decoded byte counts on the host. The ceiling is exactly 5,242,880 bytes. Derive a canonical lowercase extension from the allowed raster format. A recognized header is a format check and does not establish decoder validity. Reject short headers, mismatched extensions and signatures, SVG, and empty inputs. Normalize the filename stem to NFC, remove reserved characters and controls, trim trailing dots and spaces before testing for device aliases, and truncate without splitting UTF-8 code points. Keep the display name for alt text. Encode the final URI path segments exactly once, including parentheses, and run the generated reference through `resolveWorkspacePath`. The test suite checks the candidate reference with the existing resolver and exercises it through provider preview and Save.

Existing image references continue through the current document parser, serializer, and preview service. An ordinary edit leaves authored relative paths, reference syntax, and image metadata intact. Folio sends validated preview bytes into the existing CSP and keeps workspace directories out of `localResourceRoots`.

## Publication and recovery

1. Wait for the active view's existing edits to settle, then capture the insertion position and committed revision. If the selection or committed revision changes while the request runs, ask for a new insertion position before changing Markdown. Bind prepare, publish, and status to the initiating connection, document, and workspace. Key prepare by a stable client request ID within that connection so a retry returns the same host-issued operation ID. Serialize state changes by operation ID and reject attempts to change the payload or destination of an existing operation. Keep the operation record in VS Code workspace storage separately from the Markdown draft journals.
2. Before filesystem changes, persist the operation ID, document and root URIs, staging URI, candidate final URI, byte length, digest, and stage. Use a uniquely named staging file in the destination directory. Persist a new intended final URI before each collision retry. Verify the staged bytes, record the backend's available stage identity evidence, and publish under the chosen name with overwrite disabled. Verify that the final entry is a regular file with the expected digest and the identity that the publication operation established against the stage. Record publication before returning the relative reference. A lost reply requires checking both paths after the connection returns. If the backend cannot establish ownership after a restart, including when identity may have been reused, classify the result as ambiguous.
3. Insert the link through the existing shared edit path. The editor journal and host backup immediately checkpoint the new draft. The normal native acknowledgement still verifies the exact proposal against `TextDocument`. Save, Undo, and Redo follow VS Code's Markdown history. The binary asset may be shared or become referenced later, so Undo removes the Markdown reference and leaves the file. A status record can report a published asset independently of whether the link was acknowledged.
4. On interruption, inspect the operation record and revalidate workspace identity before reading either path. If neither file exists, prompt for reselection when the originating bytes are gone. If an owned stage still exists, verify it before offering retry or cleanup. A finalized file with matching bytes and verified publication identity can supply its relative path for explicit insertion or copy. Identical bytes alone leave ownership ambiguous. Recovery never inserts text automatically after a restart. A rename, deletion, changed root, or conflict requires a fresh insertion decision. Only remove a staging file through a backend that preserves its ownership check through deletion. Never automatically remove a published or ambiguous file. Markdown recovery remains available independent of the operation record.

## Implementation and acceptance tests

| Step | Code ownership | Acceptance coverage |
| --- | --- | --- |
| Validate paths and bytes | Host resource service and pure helpers near `src/host/vscode/resourcePath.ts` | Relative paths round-trip from nested documents and filenames with spaces, Unicode, `%`, `#`, and parentheses. Reject traversal, encoded separators, device names, cross-root paths, different authorities, symlink components, false MIME labels, SVG, and oversized or truncated inputs. | Stage and publish | New host attachment service and workspace-scoped operation records | Inject create, partial write, permission, quota, and rename failures.
