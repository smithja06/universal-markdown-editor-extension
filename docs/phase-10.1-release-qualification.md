## 4. Native Save failure and recovery results

`extension/src/verifiedReplace.ts`, `binarySave.ts` and `localVolume.ts` were reviewed. The writer now writes in bounded 1 MiB chunks and accepts test-only faults (`ReplaceFaults`) before a chunk and before the flush. The restore path never uses them.

| Fault | Test | Result |
| --- | --- | --- |
| Disk-full error (`ENOSPC`) partway through the write | `verifiedReplace.test.ts` | The previous bytes are restored and verified. The journal is removed. |
| Failed flush (`EIO` before `fsync`) | same | Previous bytes restored. Journal removed. |
| Write fails and the rollback cannot run (handle lost) | same | Error names the save journal. The journal is kept and classifies the file as `interrupted`. |
| Journal cannot be stored | same | Save fails before any byte of the document is written. |
| Cancelled after the journal is written | same | File unchanged. That save's journal is removed. |
| Conflict when an earlier interrupted journal exists | same | `ReplaceConflictError`. The earlier journal is kept. |
| Ambiguous bytes matching neither side | same | Classified `external`, never auto-recovered |
| Writer process killed by the OS mid-write, holding the exclusive lock with half the replacement on disk | same, a real child process sent `SIGKILL` | Disk holds mixed bytes. The journal classifies them as `interrupted`. A retry completes the save to the journaled replacement and removes the journal. |
| Verification failure, competing locks, external write, delete and rename attempts, stopped writes, Save As overwrite refusal | Existing Phase 10 tests | Pass |

**Defect fixed.** A save that failed after writing its journal but before writing the document, such as on cancellation, left a stale journal. A save that failed its fingerprint check could also delete a journal left by an earlier interrupted save. Now a failed save removes only the journal it wrote, and only when the file is verified to hold the previous bytes.

**Limits that remain.** Folio does not claim immunity to power loss, firmware write caching or hardware failure. The journal and the exclusive lock bound the damage to a recognizable, recoverable state on qualified Windows NTFS. Unqualified hosts use reviewed copies. The threat model is unchanged.
